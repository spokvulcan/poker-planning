# Tests sign in through a guarded seam and prove each guarantee in the cheapest layer

**Status:** accepted — decided on [map #253](https://github.com/spokvulcan/poker-planning/issues/253) via [#281](https://github.com/spokvulcan/poker-planning/issues/281). Specified, not yet built.

The retro is the first feature whose correctness is mostly *who sees what*: a hidden card is a silhouette for everyone but its author ([ADR-0015](0015-a-hidden-retro-card-is-a-silhouette-projected-by-the-shared-stage.md)), the shared stage pointer moves every browser at once ([ADR-0010](0010-a-retro-stage-projects-and-defaults-but-never-forbids.md)), a Team fixes who may read history ([ADR-0008](0008-a-team-is-the-permanent-visibility-boundary.md)), and the join policy admits by account kind ([ADR-0013](0013-retro-permissions-extend-the-one-decision.md)). The existing Playwright suite (`tests/`, one `chromium` project, four workers over one shared Convex dev deployment) already runs several browser contexts per test, but every identity it can mint is anonymous: permanent sign-in is magic link through Resend or Google OAuth, neither automatable, and Team membership requires a permanent account. CI runs lint and `ts:check` only. Meanwhile the repo has three cheaper layers, `convex-test` under edge-runtime, jsdom hook tests and node unit tests, where most of the privacy guarantees can be proven without a browser.

So: **every retro guarantee is proven in the cheapest layer that can prove it, Playwright is reserved for facts that need two real browsers against one deployment, and the browser gets a permanent account through a secret-guarded test seam that captures the real magic link instead of sending it.**

## Considered Options

- **Mint a BetterAuth session from a Convex mutation** (rejected). Depends on BetterAuth exposing server-side session creation and fakes the one path a permanent account actually takes.
- **Intercept the Resend request** (rejected). Depends on Resend's request shape and the token format inside the URL, both outside this repo's control, and needs a key in every test environment.
- **Capture the magic link in-house** (chosen). When `TEST_AUTH_SECRET` is set on the deployment, the `sendMagicLink` hook in `convex/auth.ts` writes `{email, url}` to a `testMagicLinks` table instead of calling Resend; a secret-guarded query returns the newest link for an email; the Playwright fixture visits it. The sign-in path runs end to end and the only test-specific code is one branch in one hook.
- **Prove Teams only in `convex-test`** (rejected). Leaves the join policy, `claim` and the history row unproven in a browser, which are exactly the multi-identity behaviours.
- **Click through five stages to reach `discuss`** (rejected). Minutes per test. State before the transition under test is seeded; the transition itself is always performed through the UI.
- **A separate Playwright config and server for retro** (rejected). Two dev servers on one machine is the port-3000 conflict the suite already suffers from, and both suites share auth.

## Consequences

- **The layer rule**, written into the spec: `convex-test` proves the reveal projection in both attribution modes, the ratchet stripping `authorId`, `evaluateJoin` and the retro category table, `requireRoomReader` against `requireRoomMember`, `claim` and `owner-present`, the four `ConvexError` codes ([ADR-0022](0022-the-canvass-only-local-state-is-the-hand.md)), dot budgets, walk scoping and `raise` ([ADR-0023](0023-the-walk-covers-what-was-voted-for-and-a-person-raises-the-rest.md)), coverage arithmetic, `retained` and the sweep ([ADR-0019](0019-retention-follows-the-team-and-export-never-widens-access.md)), the hourly-coarse activity patch ([ADR-0018](0018-the-activity-chokepoint-owns-the-clocks-precision.md)), nudge recipients and reminder scheduling ([ADR-0020](0020-a-nudge-is-sent-by-a-person-and-a-reminder-by-a-date.md)), the cascade and the export projections. jsdom proves the hand, single-flight per row, rollback by error kind, `clientId` dedupe, zoom-level derivation, tap-select state and the walk panel. Node proves format seeds, prompt copy and the register-bound strings. Nothing is tested in Playwright that a cheaper layer already proves, and every Playwright scenario names the cross-browser fact it exists for.
- **The test seam** is one secret-guarded module: the magic-link capture, a seeding mutation that builds a retro at a named stage through the model layer's own functions (never raw inserts, so it cannot produce rows the app could not), a `deleteTestRun` mutation, and nothing else. Every function checks the secret first and is inert without it. It is deployed everywhere and armed nowhere but test deployments.
- **Teardown.** Team retros are retained forever by design, so each fixture deletes the Team it created, cascade included, and every seeded row carries a `testRun` id so an aborted run can be cleared. `admin:dangerouslyDeleteAllData` is not part of any test.
- **The canvas contract gains data attributes** and they are spec, not test pollution: the board root carries `data-zoom-level="detail|headline|shape"` and `data-stage`; each card carries `data-card-id`, `data-hidden`, `data-cluster-id` and `data-late`; the walk panel carries `data-covered` and `data-remaining`. Retro specs assert on these with web-first assertions and never on transforms or `waitForTimeout`.
- **Twelve Playwright scenarios**, each a cross-browser fact: silhouette then reveal on advance; the shared pointer governs a view navigated ahead; join policy admits a team member and refuses a guest; a non-member attendee cannot reach the team page or another team retro; grouping another person's cards keeps their positions and shows the cluster at shape zoom; vote budget refused locally and the tally hidden until advance; seeded `discuss` with readout, late-card marker and raise; an action item's round trip through the team page's count line; the ratchet drops authors in the other browser with no undo; a drag settles for the other browser with nothing moving mid-drag; a phone-viewport guest writes a card a desktop context sees as a silhouette; write-time disclosure on a teamless and a team retro.
- **Pointer drag is automated, touch gestures are not.** Tap-select-then-group is a sequence of taps and works under mouse emulation; real touch, pinch-zoom and proximity hulls go to a manual checklist. Mobile is one Playwright project on a Pixel 5 viewport running the `@mobile` subset, because the phone's async-collection case is the bet [ADR-0011](0011-the-retro-board-is-one-canvas-with-semantic-zoom.md) rests on and needs only viewport emulation.
- **Suite shape.** Retro specs under `tests/retro/`, page objects under `tests/pages/retro-*.ts`, fixtures extended with `teamMember` and `anonymousGuest` contexts, `convex/retro.seeds.ts` beside `analytics.seeds.ts`. Same `playwright.config`, same port-3000 pin, same server lifecycle.
- **CI.** The spec requires vitest in `ci.yml`, because the convex-test layer is where the privacy guarantees live and it needs no server. Playwright stays local until a Convex preview deployment exists for CI, and the spec says so rather than leaving it implied.
